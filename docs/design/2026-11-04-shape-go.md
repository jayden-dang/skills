# `/shape #N --auto --go` — from a road to a pull request, unattended

Date: 2026-11-04. Status: **Draft — awaiting the owner's go on this design.** Method: `author-skills`.
Every change below ships only after its own RED, and the RED it answers is named beside it.
RED evidence: `.skills/SHAPEGO/red/findings.md` (fixtures `mk-a.sh`, `mk-b.sh`, stub `gh`).

## 1. What the owner asked for

The owner researches and writes the roadmap: milestones, roads, what each must deliver. From a
road onward, one command does everything up to a pull request: the spec, a draft PR with the spec
film, the build, a finished PR with a film of the real app, the data model, and whatever else the
owner needs to understand it, all generated from the code and the running application. The owner's
part ends at reading the PR and merging.

Rulings, 2026-11-04:

1. `--go` is the approval of the spec. The `Approved` stamp quotes the command.
2. Unattended acceptance may use `agent-browser` (or `kimi-webbridge`) and signs in by itself:
   dev data is local and the app is on localhost.
3. Migrations may be written, and run only against a local database.

## 3. The flow

```
road (owner)                     conductor (the session the owner typed in)
  │                                │
  ├─ /shape ROAD-N --auto --go ───►│ 0. brief-road says Ready → ticket for the road (C6)
  │                                │ 1–8. as today: charter, work + interpret, receipt, audit, final review
  │                                │ 9. film of the spec, the sheet
  │                                │ 10g. hard stop? → end at the sheet, no build
  │                                │      else stamp Approved (quoting the command), publish Ready,
  │                                │      push the branch, open a DRAFT PR (sheet + spec film)
  │                                │ 11g. open <slug>-build in WT: /deliver-issues #N (C1)
  │                                │        build-in-waves → inspect-change → polish? →
  │                                │        validate-feature (agent-browser, own login) →
  │                                │        front end changed? write-dogfood → run-dogfood (C8) →
  │                                │        close receipt → land-branch: PR ready, ticket in-review
  │                                │ 12g. evidence on the final code SHA (C4, C5), attached to the PR
  │                                │ 13g. one message: PR, Needs a decision before merge, what was not run
  ▼
owner reads the PR, merges
```

Each session commits locally; the conductor does every push, PR and tracker write except those
`land-branch` and the build's tracker sync already own. In one earlier run, auto mode refused a
peer session a tracker write.

## 4. Changes

### C1. The conductor dispatches the build; it writes no code (answers A1, A5, A6, A7)

`shape` `auto.md`, a `--go` branch after step 9. The conductor opens a third tmux session,
`<slug>-build`, in `WT`, with the prompt `/deliver-issues #N` and the charter's build section.
Not `/go`: `go` is user-invoked, and a model-invoked hand-off to it is a dead end
(`scripts/lint-write-handoffs.py`). `deliver-issues` is what `/go` runs.

The Iron Law gains a line: the conductor writes no code, as it writes no spec. A1, A5, A6 and A7
are then answered by the chain `deliver-issues` already runs and tests: task review, whole-branch
review, acceptance, close receipt, ship guard, tracker sync, occupancy, and `speak-outer` PR text.

**Needed in `deliver-issues` §2.1:** it branches from `Default PR base` with no exception. Add
one line: a ticket whose spec is committed on a branch the session is already on builds on that
branch. Without it, the build cannot see a spec that exists only on `feat/<slug>`. This is the
same gap that sits today between `/shape --auto` and `/go`, read from the text and never run.
Test depth: a shape check.

### C2. The Iron Law under `--go`

`--go` moves the approval to the command. The sheet is still written, because the owner reads it
later. Before the stamp, the charter's hard stops still end the run at the sheet with nothing built:
money, two contradicting Locks, a vision change or pivot. The spec's "Needs you" items go into the
PR under **Needs a decision before merge**, the heading `board.py` already reads.

The charter's "no push and no PR" line gets a `--go` exception: the conductor pushes `feat/<slug>`
and opens the draft. The migration hard stop becomes: write it, and run it only against a local
database. Use, in order: the worktree's own database where the repo provisions one (klynt:
`test_<worktree>_<hash>`), an isolated plane (`klynt-e2e`), and the shared dev database only
when the repo documents nothing else. A database URL that is not local stops the run.

### C3. Unattended UI acceptance (answers RED B)

`validate-ui` §2, a third driver row as a predicate, not a new default:

- **Attended** (someone is at the keyboard): unchanged. Use the operator's browser.
- **Unattended** (`deliver-issues`, or the operator says nobody is at the keyboard): use
  `agent-browser`, or `kimi-webbridge` when it is connected. Sign in with the account
  `verify.md` names for local use (`agent-browser auth save` / `auth login`, or
  `find label … fill`), never a real person's account. Only a localhost origin is driven.

The evidence stays the same file, `.skills/<CODE>/validate-ui.md`, written from a UI drive, not
from `curl`.

### C3b. Teardown by PID in acceptance

`validate-ui` and `run-dogfood`'s `unblock.md`: stop only the PID you started, as `make-video`
step 7 already says. RED B's `pkill -f 'node server.js'` matched every such process on the machine.

### C4. The films in the PR (answers A2, A3)

- **Spec film**, at the draft: `RUN/film.mp4`, already made by step 9.
- **Demo film**, after `land-branch`: REQUIRED SUB-SKILL `make-video`, kind `pr`, `$REF` = the last
  code commit (not `HEAD`: `land-branch` adds `docs(<CODE>): record delivery` after opening),
  driven with `agent-browser` and the same sign-in as C3, migrations as C2.
- Neither film enters the branch. Both go up with `gh pr edit <N> --attach`, as a bare URL on its own
  line so GitHub plays it inline. (`gh` 2.103.3 here has `--attach`; documented limit 10 MB on Free,
  100 MB on paid; the account's plan reads `unknown`.)
- Size gate: over 9.5 MB → re-encode at a higher CRF and check again. Still over → attach the
  contact sheet PNG and say the film was too large.
- `land-branch` writes the PR body. The evidence step therefore runs after it and adds its own
  block between markers, and re-adds it if a later push rewrites the body.

### C5. "Generated" means generated (answers A4)

- A database exists → dump the schema at the base and at the head, on the local database, and
  derive the ER diagram (Mermaid `erDiagram`) and a change list from the dump.
- No database → real JSON samples from the running code, under the words "no schema exists".
- A diagram drawn by an agent (a sequence, a flow) is labelled as drawn, never as generated.
- Nothing from this step is committed to the branch. It goes into the PR body or as an attached
  image.

### C8. A product walk before the PR, when the front end changed (owner, 2026-11-04)

The owner: real products run `write-dogfood` and `run-dogfood` on any plan that changes the front
end, so an unattended run must do the same before the PR. Today the text says the opposite:
`deliver-issues` §4 marks such a PR `not walked by hand — /write-dogfood` ("the build never opens
that walk itself"), and `AGENTS.md` says the execute-family close never opens a product walk.

`execute-common` Close sequence, a predicate step between acceptance (4) and the receipt (5):
WHEN the run is unattended under `--go` AND the branch changes a browser-rendered surface (the
same file classes `inspect-ui` reads: HTML, CSS, JSX/TSX/Vue/Svelte, templates) → REQUIRED
SUB-SKILL `write-dogfood`, then `run-dogfood` on its run file. ELSE write
`skip: no walk predicate`. Dogfood fixes are commits, so the receipt follows them, bound to the
last one. `AGENTS.md` and `deliver-issues` §4 gain the `--go` exception.

RED C (`.skills/SHAPEGO/red/findings.md`, Sonnet, 1.28 USD) ran the walk unattended on RED A's
built branch. What already works, and needs no text: guide, a fresh review subagent, the review fix
loop to a clean re-check, the drive, `$DF` marks, the four-section report. What fails:

- **C8a. Defects parked unfixed.** Two real defects (one malformed POST crashes the server; `{}`
  shows "undefined: undefined") were parked with no fix attempt, as "outside this spec, your call".
  `run-dogfood` parks only after 3 attempts or a human-only blocker. Under `--go`, a defect in code
  the feature does not own still goes to `root-cause`. Its fix, and anything parked, heads the PR
  under **Needs a decision before merge**.
- **C8b. The driver.** This run found `kimi-webbridge` in `~/.claude/skills` with its daemon up and
  drove the owner's own Chrome. RED B's two runs never looked and drove nothing. Use the same driver
  rule as C3 in `run-dogfood` §3 and `unblock.md`: the run picks the driver from the rule, and does
  not depend on looking in the right place. Driving the owner's own profile signs in as the owner on
  every site, so unattended runs prefer `agent-browser`, isolated, signed in from `verify.md`.
- **C8c. Open review findings with nobody to name them.** The fix loop closed them here. A finding
  the loop cannot close goes into the PR under **Needs a decision before merge**, and the cases it
  blocks stay unrun and are listed there. No named override is invented.

The PR body carries the walk: cases run and passed, every case that failed with its fix commit, every
parked case, and the `visual` cases only an agent looked at.

### C6. From a road

`/shape ROAD-N --auto --go`: `brief-road` must say **Ready**. The conductor then files one ticket for
the road through the tracker ops and the issue format, and continues as `/shape #N`.
Test depth: a shape check.

### C7. Watching a build

Today's watcher calls a STALL after 10 minutes with no file changes, and `caffeinate` holds the
machine for 6 hours. A build is longer: klynt's pre-push took 7.5 minutes per lock push, and one
PINWIN lane ran for 13 hours. For the build session: a stall is 30 minutes with no new commit,
no ledger line and no change under `.skills/<CODE>/`. Re-arm `caffeinate` for each stage. The build
writes `RUN/build-report.md` with `deliver-issues`' one message when it ends. The conductor reads
the PR back with `gh pr view --json isDraft,url` and treats the report as a claim, not evidence.

### C9. A model for each role (owner, 2026-11-04)

The owner uses Claude to frame, Codex to interpret and Grok to build, and wants to pick per role:

```
/shape #N --auto [--go] --work=claude-opus --interpret=codex-<model> --build=grok-<model>
```

**Resolution order:** a flag on the command, then a `Shape roles:` line in `docs/agents/project.md`
(`Shape roles: work=claude-opus, interpret=codex-…, build=claude-sonnet`), then the default
**work=claude-opus, interpret=claude-opus, build=claude-sonnet**. A preset replaces a
`--multimodels` flag. `--build` means something only with `--go`.

The default changes cost. `auto.md` step 5 pins both peers to `--model sonnet` today, because two
peers launched with no `--model` ran on the machine's Opus default. Opus for work and interpret
costs more on a spec run of about 45 minutes. The owner chose it.

Rules:

1. **Resolve each model before any session opens.** In step 1 (Check), ask that CLI for its own list
   (`claude` aliases, the Codex config and model list, `grok models`). An unknown name stops the run
   with that name. Never guess a model ID. Codex here is configured as `gpt-6-luna`; nobody has
   checked the names `codex-sol` and `grok-4.7`.
2. **Transport depends on the pair.** Claude to Claude keeps `SendMessage`. A role on another vendor
   gets one turn at a time through the conductor: a headless resume of its own session, a path plus
   a one-line ask in, a reply file out. Each such role has a tmux pane tailing its log, so the owner
   can watch. Measured 2026-11-04: `codex exec --json` returned a `thread_id`, and
   `codex exec resume <id>` kept the context (it answered from the first turn). Not measured: Grok,
   because the account returned `402 … usage balance exhausted`.
3. **Which roles may leave Claude:**
   - **interpret**: yes. The role only reads and reviews, and Codex's `--sandbox read-only` enforces
     that by sandbox, not by prompt. A different model family reviewing the spec answers the known
     limit "same model, picks it approved itself".
   - **build**: yes, after a measurement. `deliver-issues` dispatches implementer and reviewer
     subagents, the whole-branch review and the walk. Nobody has measured another CLI following
     that chain.
   - **work**: Claude only in the first version. `frame-change` relies on the scan subagent, the Skill
     tool and the user-question gates, and those are Claude Code's.
4. **Skills by path for other vendors.** `/interpret-session` is Claude Code syntax. A prompt to
   another CLI names the `SKILL.md` path to read and follow. `grok inspect` lists the owner's Claude
   skills and agents, but nobody has checked whether Grok follows them.
5. **A receipt for each vendor.** `skill_receipt.py` reads Claude Code transcripts only. It gains a
   reader for Codex sessions (`~/.codex/sessions`) and for Grok (`grok export`). A role with no reader
   reads **not checked** on the sheet and in the PR, never as passed.
6. **Same model, said aloud.** When work and interpret resolve to the same model, the sheet and the PR
   say "same model: interpret reviewed picks from its own family". The default always prints it.
7. **Vendor failure is a stall with a fallback.** Model at capacity (seen once in two Codex calls) or
   balance exhausted (Grok): retry once. Still failing: that role falls back to its default Claude
   model, and the sheet and the PR name the switch and why.

Test depth: rules 1, 2 (Claude pairs), 6 and the resolution order are a shape check, done with C1/C2.
`--interpret=codex-…` is a spike against a Claude interpret on the `mk-a.sh` fixture: same spec,
what each one catches. `--build=grok-…` reruns RED A with a Grok build, once its balance is topped up.

## 5. Out of scope

- Company repos: specs are private there and nothing goes onto PRs. No `--go`.
- Merging. The owner merges.
- `/tend-pr`: CI watching stays a separate command.

## 6. Order of work

1. Wait for the `spec-sheet` session to land its edits to `shape` (`auto.md`, the charter, the sheet).
2. C3 + C3b: RED B exists; write the text and run GREEN on Sonnet and Haiku.
3. C1 + C2: RED A exists; GREEN on the `mk-a.sh` fixture with a live build session.
4. C8: RED C exists; GREEN on its fixture (C8a, C8b), then inside the C1 run.
5. C4 + C5: GREEN on the same fixture. C4's 10 MB fallback is tested against the stub `gh`.
6. C6, C7: shape checks. C9 role flags, preset, default and Claude-only resolution go with step 3.
7. C9 `--interpret=codex-…`: the spike, then the Codex receipt reader.
8. C9 `--build=grok-…`: RED A with a Grok build, after the owner tops up the balance.
9. A real run on a small NAVORI or klynt road.

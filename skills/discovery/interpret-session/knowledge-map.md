# Cumulative knowledge map

Show how the decisions form one system, not only when they happened.

When **three or more** decisions interact through a flow, boundary, or dependency, precede the table with **one smallest system sketch** showing those edges.

Then render one compact table: `mechanism → depends on → decisive reason + cost accepted → evidence/confidence → still open or reopen trigger`.

Include what this session amended versus the other window inside the relevant cell, not as a history-only column. The per-turn ledger shows the step; this map shows the system and the user's current knowledge of it.

# Rehearse transfer

## Role

REQUIRED: read sibling `ROLE.md` (coach default, produce-first, evidence gate, config paths).

## Contract

Rehearsal produces two or three named moves, the chunks that serve them, one spoken run under
time, and at most five fallback lines — not a script. Debrief produces the errors, the
avoidance list, and links from real-pressure successes into `capability-map.md`. Real events
are the only place unprompted use under pressure can be observed, which makes the debrief the
vault's highest-grade evidence.

## Branch

Event is in the future → **Rehearse**. Event already happened → **Debrief**. Both pending → rehearse now, debrief after.

## Rehearse

1. Name the event, the learner's role in it, and the two or three **moves** it will actually demand: report status, disagree with a proposal, ask for clarification, explain a technical concept to a non-expert, push back on a deadline.
2. Pull the functional chunks for those moves from `lexicon.md`. Missing → REQUIRED SUB-SKILL: use `build-lexicon` before rehearsing.
3. Rehearse aloud, under time. REQUIRED SUB-SKILL: use `run-voice-session` for the rehearsal itself, with the event's moves as the focus.
4. Write at most five **fallback lines** for predictable breakdowns: lost the thread, did not catch a question, need thinking time, forgot a word mid-sentence, asked something they cannot answer. Fallbacks are the difference between a stumble and a freeze.
5. Keep the output at the level of moves and fallbacks. A word-for-word script gets read aloud, trains reading, and collapses the moment an unscripted question arrives.

## Debrief

1. The learner reports: what worked, where they switched to the support language, **what they wanted to say and did not**, and what they failed to catch.
2. The avoidance list is the primary finding. A structure or function they routed around produced no error and is invisible to `errors.md` — file it as a capability row and feed it to the next `plan-cycle` as avoidance-set material.
3. Errors → `errors.md` through `diagnose-output` if a recording or transcript exists; from the learner's own report if not, marked as self-reported.
4. Successes under real pressure → evidence toward R3 (automatic under pressure), linked to the event and dated. Log them even when the event simply went well.
5. Write `sessions/<date>-transfer.md` (`kind: transfer`).

## Rationalizations

| Thought | Reality |
|---|---|
| "It went fine, nothing to log" | Fine under real pressure is exactly the evidence practice cannot manufacture |
| "Write me the full script, it's safer" | A read script trains reading. Moves plus fallbacks train speaking |
| "No errors happened, so nothing to fix" | What they avoided saying is the finding |
| "They can't remember the details" | Then log the moves and the avoidance. Partial evidence beats none |
| "Rehearse by typing, it's faster" | The event is spoken. Rehearse spoken |

## Red flags

- A word-for-word script handed over
- A debrief with no avoidance question asked
- A successful real event that left no evidence link
- Rehearsal done in text for a spoken event

## Done when

Rehearsal: moves named, chunks available, spoken rehearsal run, ≤5 fallbacks written. Debrief: avoidance captured, errors filed, real-pressure successes linked as evidence, transfer note written.

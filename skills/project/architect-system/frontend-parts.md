# The parts of a front end

Read when the project has a client a person uses: a web app, a desktop app or a mobile app. Each
row below is one more row in the note's **Parts** table, after the parts in `parts.md`, with the
same statuses. A row that does not apply to this client (offline for a public marketing site, URL
routing for a desktop app) says **not needed yet** and why. The visual system (tokens, components)
belongs to `codify-design-system`.

| # | Part | Pin before choosing | A keeping check usually looks like |
|---|---|---|---|
| F1 | **Rendering and the UI thread**: static, client-rendered, server-rendered or server components per route class on the web; what may run on the UI thread in a native app | Device class and network, SEO needs, whether a server runtime can be operated, what freezes the window today | A route-to-mode table checked in CI; a lint or test that blocking I/O is not called from render or UI-thread code |
| F2 | **Navigation**: routes, what state lives in the URL or deep link, code-splitting, auth-gated screens | Which screens users share, bookmark or open from a notification | A route table test; a test that every gated route redirects when signed out |
| F3 | **Client state**: where server data, URL state, form state and local UI state each live; when a global store is allowed | Which data the server owns, which screens show the same data, what must survive a reload or restart | A lint that server data is not copied into the global store; a test per state home |
| F4 | **Client data access**: the typed contract (OpenAPI, GraphQL or RPC schema), one client, timeouts, retries, cancellation, optimistic updates, realtime | Who owns the contract, the server's error model, how often data changes | Generated client checked against the schema in CI; a test that a slow call times out |
| F5 | **Version skew**: an old client against a new server, and the reverse | How long an old client stays alive (cached bundle, unupdated install), the server's change policy | A contract test of the current client against the next server version; a check that the client reports its version and handles "upgrade required" |
| F6 | **Forms and validation**: shared schema, server-side validation as authority, error display, double submit | Which rules the server enforces, what a lost submit costs | A test that a server-rejected value shows its message and keeps the input; an idempotency key on submits |
| F7 | **Accessibility**: the conformance target (WCAG 2.2 AA on the web), keyboard and focus on navigation and in dialogs, names on icon-only controls, the platform accessibility tree on native | Who uses assistive technology today, the legal driver, whether the toolkit exposes an accessibility tree (measure it, do not assume it) | axe in component and end-to-end tests plus a manual screen-reader pass; a component API with no unlabelled icon button |
| F8 | **Internationalization**: message format, locale resolution and fallback, plurals, dates and numbers, right-to-left | Which locales ship, who translates, whether text is ever built by concatenation | A lint against string concatenation in UI text; a pseudo-locale test |
| F9 | **Performance budget**: Core Web Vitals at the 75th percentile on the web (LCP 2.5 s, INP 200 ms, CLS 0.1), bundle size per route; frame time and startup on native | The target device and network, today's measured numbers | A CI budget (bundle size, Lighthouse or equivalent) that fails the build |
| F10 | **Client security**: raw-HTML sinks, Content Security Policy, where tokens and session ids live (never `localStorage`), third-party scripts | The auth model (backend-for-frontend or tokens in the client), which content comes from users | A lint banning raw-HTML sinks outside one sanitizing component; a test that the CSP header is present; a grep that no token touches `localStorage` |
| F11 | **Offline and local persistence**: what works without a connection, local storage format and migration, conflict on reconnect | Where users lose signal, what a lost local write costs | A test that a write made offline is sent once on reconnect; a migration test for the local store |
| F12 | **Client observability**: error reporting with the release version, source maps or symbols kept private, real-user performance data, a request id the user can quote | Who reads the reports, privacy rules for user data | A test that an error report carries the release version and no personal data |
| F13 | **Packaging, release and update**: cache headers for the shell versus hashed assets; signing, auto-update and store review on native | Release cadence, how users get updates, rollback | A check that the HTML shell is not long-cached; an update-channel test on native |
| F14 | **Feature flags, analytics and consent**: flag lifecycle, flash of the wrong variant, event names, consent before non-essential tracking | Who owns experiments, the privacy law that applies | A test that no analytics call fires before consent; flags carry an owner and an expiry |

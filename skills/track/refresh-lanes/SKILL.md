# Refresh Lanes

`docs/roadmap/lanes.md` is the generated view of the parallel lanes each `## Focus` entry
implies: what is in build, what is ready, who claimed what, who waits for a slot. It is
only as current as its last regeneration, so every skill that writes one of its inputs
calls this one right after the write.

Two baseline landings with no such call merged a feature, stamped it `Implemented`,
pushed, and left `lanes.md` reading "In build" for it, with the next item still waiting on
it. One said the file "is generated by `/chart-progress` … so run that to refresh it"; the
other that roadmap edits belong to `plan-milestones`. A real roadmap's file went fourteen
days without a regeneration while deliveries were recorded under it.

## Run it

From the repo root, `<skill>` being this skill's folder:

```bash
d=.skills/dashboard; today=$(date +%F)
python3 <skill>/scripts/extract.py . --today "$today" --out "$d/$today.json"
gh issue list --state open --json number,title,assignees,labels,updatedAt,state --limit 500 > "$d/issues.json"
python3 <skill>/scripts/lanes.py "$d/$today.json" --issues "$d/issues.json" \
  --tracker-read "$(date -u +%FT%TZ)" --out docs/roadmap/lanes.md
```

Claims come from open GitHub issues. With another tracker, or no `gh` access, skip the
`gh` line and drop `--issues` and `--tracker-read`; the file then says claims were not read.

`lanes.py` prints one word, and the word decides what follows:

| Printed | Then |
|---|---|
| `written` | Put `docs/roadmap/lanes.md` in the commit that carries the record you just wrote. When that commit is already made, commit it alone as `docs(roadmap): refresh lanes`, and push it wherever the record was pushed. When the caller writes no commit, leave it beside the uncommitted record. `git check-ignore -q docs/roadmap/lanes.md` succeeding means the file is private: leave it written and uncommitted, never `git add -f` |
| `unchanged` | No lane line moved; only the header would have. Nothing to stage |
| `no Focus` | The roadmap has no `## Focus`, so there are no lanes. Nothing to stage |
| `not on <base>` | The record sits on a branch other than `Default PR base:`. Leave it: the file is regenerated where the record lands on the base, and a copy written on a branch conflicts with every other branch's copy at merge |

Say the printed word in your report, beside the record it followed.

*Done when: `lanes.py` printed its word and the table's action for it is done.*

## The file is generated

Never edit `lanes.md` by hand, and never correct a line in it. A wrong line is fixed at
its source — `## Focus`, an `After:`, a catalog status, a `Delivered-by:`, or the issue —
and then this skill runs again.

## No-op

No `docs/roadmap/INDEX.md`: there are no lanes. Say so and stop.

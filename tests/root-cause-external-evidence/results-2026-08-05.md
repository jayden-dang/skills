# root-cause external evidence — RED baseline results

Model roster: `gpt-5.6-sol`, `gpt-5.6-terra`.

## RED

All four runs selected option A, but none completed the external evidence gate
before returning. They captured or proposed runtime identity and said that docs
would be fetched later.

Verbatim omissions:

- `gpt-5.6-terra`, OpenObserve: “then resolve version-matched official
  OpenObserve ingestion docs” — future action; no resolved source or comparison.
- `gpt-5.6-terra`, Redis: “then fetch the matching provider’s documentation” —
  future action; no owning source or comparison.
- `gpt-5.6-sol`, Redis: every documented-expectation cell was “pending matched
  docs.”

The pressure stack did not make the models patch from memory, but it did make
them stop at an evidence-collection plan and proceed as if choosing A were the
gate. The missing behavior is deterministic: when a minimized failure crosses a
versioned external dependency, the run needs a completed identity + owning-docs
+ actual-versus-documented artifact before Phase 3.

## Failure classification

- Observable conditional: external/versioned dependency is on the minimized
  failure path.
- Omitted required elements: resolved owning source, version applicability,
  actual-versus-documented comparison, and unresolved/conflict disposition.
- Correct form: conditional recipe with REQUIRED slots and a checkable completion
  criterion.

## GREEN

Both models completed evidence artifacts for OpenObserve and managed Redis rather
than returning a future plan. They resolved current official documentation when
possible, kept runtime identity/version applicability explicit, filled the
contract diff, rejected memory/provider assumptions, and blocked Phase 3 when
applicability remained unresolved.

## Meta-test

The weakest model found the gate clear, especially the rule that unresolved
applicability blocks external-behavior hypotheses. It identified two remaining
ambiguities: the artifact could rely on a handoff assertion rather than citing
the literal Phase 1 signal, and current docs needed an explicit reference-only
disposition when runtime access was unavailable. Both are now required by the
gate check and no-access template.

## REFACTOR

The weakest model was rerun with no literal Phase 1 output and no runtime access.
It used the required unavailable-evidence disposition, treated current OpenObserve
docs as reference-only, filled applicability as unresolved, blocked Phase 3, and
did not authorize the remembered endpoint patch.
